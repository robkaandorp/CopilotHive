Increase xUnit test parallelism from 1 to 8 threads

Original serialization (maxParallelThreads: 1) was added to fix a STATE_DIR
race in ProgressDocumentTests, but went further than necessary and slowed
the now much-larger suite considerably. Root-caused two additional classes
mutating process-wide env vars (GH_TOKEN/GITHUB_TOKEN/OLLAMA_API_KEY/
OLLAMA_URL) outside the existing EnvVarMutation collection, and one class
mutating Console.SetError outside the ConsoleOutput collection - all could
race under parallel execution:
- PipelineHelpersTests, ModelDiscoveryServiceTests: added
  [Collection("EnvVarMutation")] (DisableParallelization=true).
- TaskExecutorSessionTests: added [Collection("ConsoleOutput")]
  (DisableParallelization=true).

Set maxParallelThreads to 8 (test-class-level parallelism; most classes
spin up real WebApplicationFactory/Kestrel hosts, so going near the full
28-core count causes thread-pool contention rather than speedup).

Verified stable across 3 consecutive full-suite runs: 4465 passed, 0
failed, 2 skipped each time, ~2m7s-2m29s vs ~5m40s fully serial.
